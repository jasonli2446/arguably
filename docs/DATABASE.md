# Database Schema Documentation

## Overview
This document describes the database schema for Arguably.

## Enums

### UniversalRole
- `ADMIN` - System administrator with full access
- `USER` - Regular user

### SessionRole
- `HOST` - Session creator, can start/end sessions
- `MODERATOR` - Manages session flow, can pause/resume
- `DEBATER` - Active participant in the debate
- `AUDIENCE` - Observer, can become a debater

### SessionType
- `ONE_ON_ONE` - Two debaters
- `EXPERT_VS_CROWD` - One expert vs. multiple debaters
- `TEAM` - Crowd vs. crowd
- `PANEL` - Panel discussion format

### SessionStatus
- `WAITING` - Awaiting participants to join
- `LIVE` - Active debate in progress
- `PAUSED` - Temporarily paused
- `ENDED` - Debate concluded

## Models

### User

Represents a platform user account.

**Fields:**

| Field | Type | Constraints | Default | Notes |
|-------|------|-------------|---------|-------|
| `id` | UUID | PK | - | Generated by Supabase Auth |
| `username` | String | UNIQUE | - | - |
| `email` | String? | - | null | Optional |
| `realname` | String? | - | null | Display name |
| `role` | UniversalRole | - | USER | System role |
| `created_at` | DateTime | - | now() | Account creation |

**Relations:**
- `hosted_sessions: Session[]` - Sessions created by this user
- `moderated_sessions: Session[]` - Sessions moderated by this user
- `participates_ins: ParticipatesIn[]` - All session participations

---

### Session

Represents a debate session/room.

**Fields:**

| Field | Type | Constraints | Default | Notes |
|-------|------|-------------|---------|-------|
| `id` | String | PK | CUID | - |
| `code` | String | UNIQUE | - | Room code (e.g., "ABC123") |
| `name` | String | - | - | Session title |
| `description` | String? | - | null | Optional details |
| `host_id` | UUID | FK → User | - | Session creator |
| `moderator_id` | UUID? | FK → User | null | Optional moderator |
| `type` | SessionType | - | - | Debate format |
| `status` | SessionStatus | - | WAITING | Current state |
| `debater_capacity_proponent` | Int? | - | 1 | Max proponent slots |
| `debater_capacity_opponent` | Int? | - | 1 | Max opponent slots |
| `debater_capacity_panel` | Int? | - | 5 | Max panel slots (PANEL only) |
| `audience_capacity` | Int | - | 10 | Max audience slots |
| `turn_length` | Int | - | 120 | Turn duration (seconds) |
| `created_at` | DateTime | - | now() | Creation timestamp |
| `ended_at` | DateTime? | - | null | End timestamp |

**Relations:**
- `host: User` - Session creator
- `moderator: User?` - Session moderator (optional)
- `participates_ins: ParticipatesIn[]` - All participants

**Notes:**
- The term "proponent" refers to the debaters that agree with the host
- Similarly, the term "opponent" refers to the debaters that disagree with the host

---

### ParticipatesIn

Join table tracking user participation in sessions.

**Fields:**

| Field | Type | Constraints | Default | Notes |
|-------|------|-------------|---------|-------|
| `user_id` | UUID | PK, FK → User | - | - |
| `session_id` | String | PK, FK → Session | - | - |
| `joined_at` | DateTime | - | now() | Join timestamp |
| `left_at` | DateTime? | - | null | null = still active |
| `session_role` | SessionRole | - | AUDIENCE | User's role in session |

**Relations:**
- `user: User` - Participant
- `session: Session` - Session

**Primary Key:** Composite `(user_id, session_id)`

---

## Relationships

```
User
├─ (1) ─ hosts ─ (Many) → Session ─ has ─ (Many) → ParticipatesIn
├─ (1) ─ moderates ─ (Many) → Session
└─ (1) ─ participates ─ (Many) → ParticipatesIn
```

## Capacity Calculations

### Total Session Capacity

**Formula:**
```typescript
// for ONE_ON_ONE, EXPERT_VS_CROWD, TEAM:
totalCapacity = 
totalCapacity = debater_capacity_proponent 
              + debater_capacity_opponent 
              + audience_capacity 
              + 1  // moderator slot

// For PANEL:
totalCapacity = debater_capacity_panel
            + audience_capacity + 1
```

**Example (ONE_ON_ONE):**
- Proponent: 1 slot
- Opponent: 1 slot
- Audience: 10 slots
- Moderator: 1 slot
- **Total: 13 slots**

**Example (PANEL):**
- Panelists: debater_capacity_panel (e.g., 5)
- Audience: audience_capacity (e.g., 50)
- Moderator: 1 slot
- **Total: 56 slots**

### Debater Capacity

**Formula:**
```typescript
// For ONE_ON_ONE, EXPERT_VS_CROWD, TEAM:
totalDebaterCapacity = debater_capacity_proponent + debater_capacity_opponent

// For PANEL:
totalDebaterCapacity = debater_capacity_panel
```

## Constraints & Rules

| Constraint | Description |
|-----------|-------------|
| `User.username` | Must be unique across all users |
| `Session.code` | Must be unique across all sessions |
| `Session.moderator_id` | Optional; can be null initially |
| `ParticipatesIn.left_at` | null = actively in session |
| `Session.ended_at` | null until session ends |
